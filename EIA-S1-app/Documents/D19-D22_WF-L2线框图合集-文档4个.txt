## WF-L2-1 模板列表页 (Template List Page)

交互原型框架 (Wireframe Blueprints) - L2 层（模板与流程设计层）

### 📘 页面概述

显示所有 RUP 模板，支持搜索、过滤、版本查看与创建新模板。

---

### 页面结构与区域编号

```
┌────────────────────────────────────────────┐
│ 顶部导航栏（A区）                           │
├────────────────────────────────────────────┤
│ 过滤与搜索栏（B区）                         │
├────────────────────────────────────────────┤
│ 模板卡片列表（C区）                         │
│ ├── 模板卡片 (C1)：模板名称、版本、状态、操作 │
│ ├── 模板卡片 (C2)：hover 显示"编辑/复制/删除"│
│ └── 分页条 (C3)                              │
├────────────────────────────────────────────┤
│ 新建模板按钮浮层（D区）                     │
└────────────────────────────────────────────┘
```

---

### 区域说明

| 区域 | 内容 | 功能 / 操作 |
|------|------|-------------|
| **A** | 顶部导航栏 | 与 L1 一致，包含"模板中心"高亮 |
| **B** | 搜索与过滤栏 | 按模板名称、分类、状态过滤；排序方式选择 |
| **C1/C2** | 模板卡片 | 展示模板摘要，点击进入 WF-L2-2 模板编辑器 |
| **C3** | 分页条 | 分页与跳转控制 |
| **D** | 新建按钮浮层 | 固定在右下角，"＋ 新建模板" 进入空白编辑器 |

---

### 模板卡片显示信息

每张模板卡片（C1）展示以下信息：

- 模板名称
- 分类（Standard / Simplified / Agile / Custom）
- 状态徽章（见下方状态说明）
- 工作流数量
- 节点总数
- 最后更新时间

> 📌 v5.0补充：模板状态对应 `TemplateStatus` 枚举：
> - **Draft**：草稿编辑中（灰色）
> - **Published**：已发布可用（绿色）——可被项目引用
> - **Archived**：已归档（灰色）——不可被新项目引用
> - **ValidationFailed**：验证失败（红色）——保存被阻断

## WF-L2-2 模板编辑器 (Template Editor)

### 📘 页面概述

模板建模的核心工作区，用于定义工作流、节点及依赖关系。支持拖拽式流程建模、实时循环检测与完整的验证保存流程。

---

### 页面结构与区域编号

```
┌────────────────────────────────────────────────────────────┐
│ 顶部工具栏（A区）                                           │
├────────────────────────────────────────────────────────────┤
│ 左侧工具栏（B区） │ 中央画布区（C区） │ 右侧属性面板（D区） │
│                   │                   │                      │
│                   │                   │                      │
├────────────────────────────────────────────────────────────┤
│ 底部状态栏（E区）                                           │
└────────────────────────────────────────────────────────────┘
```

---

### 区域说明

| 区域 | 名称 | 内容 / 功能 | 交互说明 |
|------|------|-------------|----------|
| **A** | 顶部工具栏 | 保存、验证、预览、撤销/重做 | 验证失败后按钮高亮"修复模式" |
| **B** | 左侧工具栏 | DocType 拖拽库，按工作流分组 | 支持拖拽节点到画布 |
| **C** | 中央画布 | 拖拽式流程建模区（ReactFlow） | 连接线即依赖，支持缩放与平移 |
| **D** | 属性面板 | 显示选中节点/边的属性 | 动态切换内容类型 |
| **E** | 状态栏 | 当前模板名、验证状态、上次保存时间 | 状态变化时动画提示 |

---

### 区域内子结构编号

**C区子区**：

- **C1**：工作流泳道背景（可折叠）
- **C2**：节点元素（显示 label、phaseCode 对应的 displayName、completionConditionType）
- **C3**：依赖连线（实线=流程内，虚线=跨流程）

**D区子区**：

- **D1**：属性表单（节点或边的可编辑属性）
- **D2**：验证错误高亮（phaseCode 不合法或循环依赖时显示）

---

### 主要交互流

| 用户操作 | 跳转 / 动作 | 说明 |
|----------|-------------|------|
| 拖入新工作流节点 | — | 调用 phaseCode 默认值计算（`DocType.AllowedPhaseCodes ∩ Workflow.allowedPhaseCodes`，均为 `List<String>`），无交集则弹窗手选 phaseCode |
| 连接依赖边 | — | 实时调用循环检测 API（`POST /api/templates/:id/check-cycle`），成环则撤销并高亮 |
| 双击节点 | — | 打开 D1 属性表单，可编辑 label、description、phaseCode、completionConditionType |
| 点击"验证模板" | WF-L2-3 | 执行完整验证，生成 ValidationReport |
| 点击"保存模板" | — | 串行执行保存流程（见下方），成功后状态→ Published |
| 点击"返回列表" | WF-L2-1 | 离开前检查未保存修改，提示保存/放弃/取消 |

> 📌 v5.0补充：实时循环检测调用后端 API `POST /api/templates/:id/check-cycle`，
> 请求体包含临时边或跨流程依赖对象。
> 响应：`{ hasCycle: boolean, cyclePath?: string[], depthExceeded?: boolean }`。
> `maxDepth` 由 `TemplateConfig.maxDepth` 配置，默认为 6。

---

### 保存流程（串行执行，v5.0 5.1节）

保存时按以下顺序串行执行，任一步骤报错则阻断：

```
Step 1：工作流完整性验证
  → 无工作流：报错阻断
  → 存在空工作流（无节点）：警告，用户可选择继续

Step 2：phaseCode 一致性验证
  → node.phaseCode ∉ workflow.allowedPhaseCodes：报错阻断
  → 高亮错误节点，提供定位导航，错误提示展示 displayName(phaseCode) 格式

Step 3：全局循环检测（DFS，maxDepth 默认6）
  → 检测到循环：报错阻断，高亮循环路径
  → 深度超限：警告，用户可选择继续

Step 4：孤立节点检查
  → 存在孤立节点：警告，用户可选择继续

Step 5：事务持久化
  → 保存 RUPTemplate、WorkflowDefinition、
    FlowTemplateNode（含 phaseCode 字段）、FlowTemplateEdge、
    CrossFlowDependency
  → 成功：模板状态 → Published
  → 失败：回滚事务，提示错误原因与重试选项
```

> 📌 v5.0补充：警告类型（空工作流、孤立节点、深度超限）允许用户确认后继续保存；
> 错误类型（无工作流、phaseCode 不合法、循环依赖）必须修复后才能保存。

---

### 操作历史（撤销/重做）

支持 **Ctrl+Z** 撤销、**Ctrl+Y** 重做。

可撤销的操作范围（v5.0 5.1节）：

- 添加/删除节点
- 添加/删除依赖边（流程内和跨流程）
- 修改节点属性（label、description、phaseCode、completionConditionType）
- 修改工作流属性（name、allowedPhaseCodes 范围）

> 📌 v5.0补充：新操作会清空重做栈；
> 撤销/重做历史在关闭编辑器时清除（不持久化）。

---

### 依赖边样式规范

| 边类型 | 样式 | 说明 |
|--------|------|------|
| 流程内依赖（required） | 实线箭头（粗） | `FlowTemplateEdge.type = required` |
| 流程内依赖（optional） | 虚线箭头（细） | `FlowTemplateEdge.type = optional` |
| 跨流程依赖（required） | 粗虚线箭头 | `CrossFlowDependency.type = required` |
| 跨流程依赖（optional） | 细虚线箭头 | `CrossFlowDependency.type = optional` |

跨流程依赖边可通过视图开关隐藏/显示（左侧控制面板）。

### phaseCode 默认值计算规则

拖入节点时系统自动计算默认 phaseCode：

```
intersection = DocType.AllowedPhaseCodes ∩ Workflow.allowedPhaseCodes
（两者均为 List<String>，执行字符串集合交集运算）

若 intersection 非空：
  从 S0 本地缓存（PhaseCache）按 PhaseDefinition.Order 升序排列
  intersection 中的 phaseCode，取 Order 最小的一个作为默认值。
  标准顺序（Order 1→4）：
    Inception(1) → Elaboration(2) → Construction(3) → Transition(4)

若 intersection 为空：
  弹出阶段选择对话框，用户手动指定；
  下拉框展示 PhaseDefinition.displayName（如"初始阶段"），
  提交时使用 phaseCode 字符串（如"Inception"）；
  提示：当前工作流允许的 phaseCode 范围
```

> 📌 v5.1更新：Phase 合法性以 `PhaseMapping` 静态配置为准，不可在线修改。
> 支持工作流（Config & Change Mgmt / Project Management / Environment）的
> `allowedPhaseCodes` 为全部四个 phaseCode（Inception / Elaboration /
> Construction / Transition），始终有交集。
> `allowedPhases`（枚举列表）字段名已废弃，统一改为 `allowedPhaseCodes`（字符串列表）。

### 退出编辑器

点击"返回列表"或关闭浏览器标签时：

1. 检查是否有未保存修改
2. 若有：弹出对话框 → [保存并关闭] [放弃修改] [取消]
3. 选择"保存并关闭"：执行保存流程后关闭
4. 选择"放弃修改"：清理操作历史，关闭编辑器
5. 选择"取消"：返回继续编辑

# WF-L2-3 模板验证结果页（Template Validation Report Page）

**文档编号：** D21  
**文档名称：** WF-L2-3 模板验证结果页线框图  
**来源状态：** Newly Added

## 📘 页面概述

模板验证结果页展示最近一次对当前模板执行验证所生成的 `ValidationReport`，包括通过/失败总体状态、全部 `ValidationIssue` 明细（按 severity 分组展示），并提供错误定位跳转、一键修复和日志导出功能。

**页面入口：**

- 从 WF-L2-2 模板编辑器顶部工具栏点击 [验证模板] 按钮
- 从 WF-L2-1 模板列表页卡片操作点击 [验证模板]

**页面出口：**

- 点击 [返回编辑器] → WF-L2-2 模板编辑器（若从编辑器进入则保留编辑状态）
- 点击 [前往模板] → WF-L2-2 模板编辑器（若从列表页进入）
- 点击错误条目中的 [定位] → 跳转到 WF-L2-2 并高亮对应节点/边

## 📘 页面概述

模板版本管理页展示当前模板的历史版本列表，支持任意两个版本之间的差异对比（左右分屏），以及版本回滚和版本复制操作。

> **重要设计说明：** S1 的"模板版本"指的是 **RUPTemplate 结构快照**（工作流拓扑、节点、依赖边的整体快照），与 S3 文档版本（DocumentVersion）完全独立。MVP 阶段版本快照通过保存时自动留存 `updatedAt` 时间戳标记，不单独建立 VersionSnapshot 表，以 `rup_template.updatedAt` + `validation_report.createdAt` 作为版本时间锚点。

**页面入口：**

- 从 WF-L2-1 模板列表页卡片操作点击 [查看版本]
- 从 WF-L2-2 模板编辑器顶部工具栏点击 [版本历史]

**页面出口：**

- 点击 [返回列表] → WF-L2-1
- 点击 [打开编辑器] → WF-L2-2
- 点击 [回滚到此版本] → 执行回滚后自动跳转 WF-L2-2

## 回滚流程

用户点击 [回滚到此版本] 后触发以下交互流程：

```
Step 1：显示回滚确认对话框
──────────────────────────────────────────────────────
"回滚确认

 即将将模板「标准RUP模板」回滚到：
 版本 v2（2026-03-15 10:30）

 回滚后：
 ● 当前版本（v3）的所有修改将被覆盖
 ● 模板状态将变为 Draft（需重新保存发布）
 ● 此操作不可通过页面Undo恢复（但 v3 仍保留在版本历史中）

 [确认回滚]  [取消]"
──────────────────────────────────────────────────────

Step 2：执行回滚
- 调用回滚 API（待 D18 补充：PUT /api/templates/:id/rollback）
- 显示进度指示器

Step 3：回滚成功
- 显示成功提示：
  "已成功回滚到 v2，当前版本为 Draft 状态。
   建议检查模板内容后重新发布。"
- 版本历史更新：在时间线顶部新增一条"v4（从v2回滚）"条目
- 自动跳转到 WF-L2-2 编辑器

Step 4：回滚失败
- 显示错误提示（含错误原因）
- [重试]  [取消]
```

当模板仅有一个版本时（刚创建未保存过第二次），B2 时间线仅显示"v1 初始版本"，B1 版本对比选择器禁用（灰化），C区显示以下空状态：

```
┌───────────────────────────────────────────────────────────────────────┐

│     该模板目前仅有一个版本，无法进行版本对比。                        │
│     每次保存模板后，系统会自动记录新版本。                            │
│                                                                       │
│                    [前往编辑器]                                       │
│                                                                       │
└───────────────────────────────────────────────────────────────────────┘
```
